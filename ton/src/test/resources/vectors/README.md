# TON vectors

`ton-sdk.json` contains expectations generated by independent official SDKs, not
published protocol test vectors and not Signet output. Normal `:ton:test` runs load
the committed JSON and need neither Node.js nor a network connection.

Sources:

- [`@ton/ton` 16.3.0](https://github.com/ton-org/ton), MIT: V3R1, V3R2, V4R2 and V5R1.
- [`@ton/crypto` 3.3.0](https://github.com/ton-org/ton-crypto), MIT: Ed25519 signatures.
- [Highload V3 revision `f5d9b592bd5ab5c9ae6ca627819929e140f6bd61`](https://github.com/ton-blockchain/highload-wallet-contract-v3/tree/f5d9b592bd5ab5c9ae6ca627819929e140f6bd61),
  MIT: unmodified TypeScript wrapper and compiled wallet code.
- [`@ton/sandbox` 0.44.0](https://github.com/ton-org/sandbox), MIT: separate TVM execution check.

The vectors cover 20 addresses across wallet versions, networks and workchains,
and 13 signed transfers: deployment, active wallets, UTF-8 comments and snake-cell
boundaries. Assertions compare state/code hashes, signing hashes, signature bytes,
envelope cell hashes and normalized external-message hashes. Equivalent BOC container
layouts are accepted; their represented cells must match.

## Reproduce

`jetton.json` contains independent `@ton/core` encodings of TEP-74 transfer (including
custom/forward payloads and empty payload) and burn messages. Regenerate with
`node jetton.cjs`; Java tests compare exact BOC bytes, including the burn payload flag.

From this directory, with Node.js installed:

```sh
npm ci --ignore-scripts
node generate.cjs /path/to/highload-wallet-contract-v3 /tmp/ton-sdk.json
cmp ton-sdk.json /tmp/ton-sdk.json
```

The Highload checkout must be at the exact revision above. Its wrapper is transpiled
without modification. The generator uses the public test seed consisting of 32 `01` bytes.

After running `./gradlew :ton:test` from the repository root:

```sh
node ton/src/test/resources/vectors/verify-sandbox.cjs ton/build/ton-sandbox-messages.json
```

This executes the actual Signet-signed envelopes exported by the Java test, checks
compute/action success, delivered value, fees, replay and expiry. It is an independent
TVM check; real RPC scenarios live in `integration-tests`.
